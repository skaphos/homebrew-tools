# homebrew-tools

Homebrew tap for Skaphos command-line tools.

| Cask | Source |
| --- | --- |
| `repokeeper` | [skaphos/repokeeper](https://github.com/skaphos/repokeeper) |
| `sting` | [skaphos/sting](https://github.com/skaphos/sting) |

## Use the tap

```bash
brew install skaphos/tools/repokeeper
brew install skaphos/tools/sting
```

## How casks are published

The casks in `Casks/` are generated by GoReleaser in each tool's release workflow and pushed
directly to `main`. Do not edit them by hand: the next release overwrites them. Change the
`homebrew_casks` section of the tool's `.goreleaser.yaml` instead.

The macOS binaries are Developer ID signed and notarized. The casks published so far still
carry a deprecated `postflight` hook that strips `com.apple.quarantine`, left over from when
the binaries were unsigned. It is being removed upstream (skaphos/repokeeper#385,
skaphos/sting#161), and each cask loses it on that tool's next release. Once those changes
ship, the casks carry no Gatekeeper workaround, and each tool's release workflow fails if the
signing credentials are missing rather than publishing an unsigned binary.

`Tap CI` runs `brew style` and `brew audit --strict --online` on pushes to `main`, on pull
requests, and on manual dispatch.
Because releases push straight to `main`, a failure there reports a problem after publication
rather than blocking it. Fix the cause in the tool's GoReleaser config. Until both tools
release without the `postflight` hook, `Tap CI` fails on `Cask/InstallSteps` and
`Cask/StanzaOrder`.

`Formula/` is reserved for formulae built from source; none exist today.

## Local validation

`brew style` takes file paths, but `brew audit --cask` resolves casks by tap name, so it
checks the copy in Homebrew's tap directory rather than an arbitrary checkout. Edit and audit
in that copy:

```bash
brew tap skaphos/tools
cd "$(brew --repository skaphos/tools)"
brew style Casks/*.rb
brew audit --cask --strict --online skaphos/tools/<cask-token>
```
